# 应用图标 · 纸见

母版是 `design/icon.png`（1024×1024，米色等高线底板上的深青 `#` 字形）。
`scripts/gen-icon.ps1` 不重绘任何线条，只从这张母版派生系统要的两个资源。

**仓库里只有这一张母版。** 换图时直接覆盖 `design/icon.png`，不要在旁边留
`file.png` / `my-icon.png` 之类的原始文件副本——母版就是那份原始文件，留副本只会
出现「哪张才是真的」这个问题，而两份同名同内容的 PNG 在 diff 里看不出区别。

## 生成

```powershell
pwsh -NoProfile -File scripts\gen-icon.ps1
```

| 文件 | 尺寸 | 内容 |
|---|---|---|
| `app_icon.png` | 1024² | 母版原样（不透明）。`AppScope` 与 `entry` 各一份 |
| `startIcon.png` | 216² | 启动窗口图标，只写 `entry` |
| `preview-216.png` / `preview-48.png` | 216² / 48² | 缩略预览，用来判断小尺寸下读不读得出 |

`AppScope/app.json5` 与 `entry/src/main/module.json5` 的 `icon` 都指向
`$media:app_icon`。幂等，可重复运行。

## 为什么是单层图标，不是 layered_image

HarmonyOS 支持分层图标（`layered_image` 指向一个 `foreground` + `background`
的 json），好处是桌面、解锁、设置里会有轻微视差。它**不是必需的**：`icon` 直接
指向一张普通 PNG 完全合法，系统用它的圆角遮罩裁剪。

这里试过分层，结论是**这条路走不通**，原因值得写下来因为它不是参数问题：

分层要求把字形从底板里抠出来，而这张母版的底板**在字形底下不可见**。能抠出来的
前提是「重建底板，再逐像素解混合」，但合成回原图的约束是

```
a ≥ k,        k = max_c |src_c − plate_c| / headroom
```

这是一个**硬下界**：只要底板在某个像素不等于 `src`，那里就必然有前景墨。底板是
重建的、天生带几个色阶误差，于是底板的纹理整片漏进前景层——上一版母版（深蓝
极光底）实测前景 PNG 783 KB，铺到中灰上看得见整片蓝云。放大 alpha 的增益会把误差
放大三倍；调阈值只能两边都伤：收紧把字形本体也切掉，放松就漏纹理。

单层没有这个问题：整张 PNG 就是最终像素。代价只是没有分层视差——而图标在
48–216 px 下看不出视差，抠图却会实实在在把边缘弄脏。

**换母版时先问一句「底板在字形底下是否已知」**：

- **已知**（上一版是 3×3 纯色马赛克，每个像素属于哪格可以算出来）→ 可以拆，
  `a = (src − bg) / (255 − bg)` 是解出来的而不是猜的，端到端断言能达到 max 通道
  误差 1。那一版的脚本与理由在 git 历史里。
- **未知**（渐变、极光、玻璃、等高线纹理、任何有机过渡）→ 走单层。当前母版的
  米色底板带等高线，字形底下那条线画到哪无法重建，所以走单层。

## 合成到桌面时注意

- 图标**不自带圆角、不带内边距**——外层圆角是系统的。母版画满 1024²，四角会被
  遮罩裁掉。
- 图形须留在安全区内：系统遮罩会裁四角，当前字形框 `x 272..750 / y 262..750`
  （479×489，四边留 272 / 262 / 273 / 273 px，都在 17% = 174 px 之外），占画布
  46.8% × 47.8%，笔画覆盖 14.3%。
- `entry/` 的副本会覆盖 `AppScope/`，所以**两处都要写**：只改一处，桌面还是旧图标，
  而两边文件名相同，看起来像「改了没生效」。
- 一个 1024² 的不透明 PNG 约 195 KB。HAP 里它会以原尺寸存在，不压缩成多档——
  这是单层图标的实际代价，换图时不用意外。压缩率取决于底板，米色底比极光底小得多。

## 依赖说明（改脚本前先读）

本机是 CLT-only，**没有 .NET SDK、没有 csc**，PowerShell 7 的 `Add-Type` 无法引用
`System.Drawing`（CS1069：找不到 `System.Drawing.Common`）。所以像素处理全部走
`Add-Type -AssemblyName System.Drawing` + `LockBits` 读写 `byte[]`，不用内联 C#。

一个 PowerShell 陷阱：变量名**大小写不敏感**。曾经用 `$N = 1024` 当画布尺寸，被
循环计数器 `$n` 覆盖，后面 `New-Bitmap($N,$N)` 就建出 4×4 的位图，表现是「预处理
全对、产物全错」。画布尺寸一律叫 `$SIDE`。
