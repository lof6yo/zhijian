# 应用图标 · 纸见

`app-icon-master.png` — 1024×1024 的原始画稿，分层图标的唯一素材源。

## 来历

- 由生图模型按「玻璃井号 / 沉浸光感」的提示词生成，2026-10-27。井号取自
  Markdown 的标题语法，天然接近正方形，比纸页更适合作图标。
- 画稿本身是**整幅方形图**：半透明玻璃井号浮在深墨蓝底板上。它不能直接当
  分层资源用 —— HarmonyOS 要求 `background.png` 是**纯色**、`foreground.png`
  是**透明** PNG。

## 生成

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\gen-icon.ps1
```

脚本会：

1. 把画稿转正（`$TILT = -6`，生图工具出来的字通常歪几度）；
2. 用红色通道**逐像素**抠出井号（底板 R≤40、玻璃 R≥140），再做 2 px 形态学闭运算
   补掉玻璃自身的暗斑 —— 不能沿用「逐行填满首尾亮像素」的旧办法，井号的四条
   笔画之间有真实空隙，逐行填会把两根竖笔连成一块板；
3. 把井号的 alpha 包围盒**拉成正方形**（`$SQUARE`）后再居中。井号本身高大于宽
   （705×772），等比缩放会让左右留白比上下宽 —— 这就是「横纵间距不协调」的来源；
   拉平后实测留白 174/173/174/174 px；
4. 在透明层上重建体积：外发光 + 接触阴影 + 玻璃本身；
5. 把底板替换成 `$PLATE`（`#0B4FA8`），写 1024² `background.png`；
6. 生成 216² `startIcon.png`（白底启动页上的墨色剪影）；
7. 同时写入 `AppScope/resources/base/media` 与
   `entry/src/main/resources/base/media` —— **模块里的那份生效**，只改一处会
   看到旧图标。

脚本末尾会自检：两张图是否 1024²、前景四角是否全透明、**中心是否透明**（井号的
中空要透出底板）、背景是否单一纯色且无透明像素。任一条不过就报错退出。

## 改图时注意

- 换掉 `app-icon-master.png` 就等于换图标；其余产物都由脚本派生，不要手改。
- 抠图是按「亮主体 / 暗底板」判定的（`Key()` 里的 40/130 两级）。换一张**暗主体 /
  亮底板**的画稿，这里要取反，否则前景会是空的 —— 脚本的 `no mark found` 会先拦住。
- 底板色写在 `$PLATE`。画稿自带的底板不用：规范不允许背景层带渐变，而且它比
  桌面需要的更深。
- 缩放围绕**画布中心**，不是围绕井号的包围盒；`$SCALE = 0.66` 是拉平后的边长占
  画布比例，四边各留约 17%。
- 画稿里笔画自己带圆角是允许的（系统遮罩再裁一次）；但**不要**给 1024 画布本人
  加圆角或内边距，那会被系统遮罩切成双层圆角。
