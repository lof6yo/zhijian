# 应用图标 · 纸见

母版是 `design/my-icon.png`（1024×1024，白色图形 + 3×3 蓝色马赛克底）。
`scripts/gen-icon.ps1` 不重绘任何线条，只把这张母版拆成 HarmonyOS 分层图标
要求的两层。

## 生成

```powershell
pwsh -NoProfile -File scripts\gen-icon.ps1
```

产出（`foreground.png` / `background.png` 写 `AppScope` 与 `entry` 两处，
`startIcon.png` 只写 `entry`），外加两张预览图。幂等，可重复运行。

| 文件 | 尺寸 | 内容 |
|---|---|---|
| `foreground.png` | 1024² | 透明 PNG，只有白色图形（带真实抗锯齿 alpha） |
| `background.png` | 1024² | 不透明，马赛克底（图形原来盖住的那块已补回） |
| `startIcon.png` | 216² | 两层合成后的小图 |
| `preview-216.png` / `preview-48.png` | 216² / 48² | 合成后的预览，不是分开的层 |

## 为什么必须拆成两层

分层图标在桌面、解锁、设置里会按不同尺寸重采样，前景层还有轻微视差。图形和底色
烤在同一张 PNG 里，任何一次重采样都会把白色边缘与蓝底混出一圈灰；分成「透明前景 +
不透明背景」之后，白永远在白层、蓝永远在蓝层，边缘才干净。这是 HarmonyOS 图标
资源的硬结构，不是可选项。

**背景层为什么可以是马赛克而不是纯色**：「背景层建议纯色」是设计建议，不是资源
校验项——它只是一张普通 PNG。花纹是刻意保留的设计。但图形底下那块**必须补成底色**：
若留白，前景层在某些缩放档位比背景层小一圈时会露出一道白边。

## 抠图方法论：反解 alpha，不猜

这里的做法不是「按亮度切白色」，而是**解混合方程**：

```
src = a × 255 + (1 − a) × bg      →      a = (src − bg) / (255 − bg)
```

能这么做的原因是 **bg 是确定已知的，不是推测的**：母版是 3×3 纯色马赛克，每个
像素属于哪一格可以算出来（格宽 `1024/3 ≈ 341.33`，边界落在半格偏移处），每格的
颜色可以从该格的可见部分投票得到。

脚本末尾有一条端到端断言：**把解出来的前景合成回背景，必须还原母版**。
当前实测 max 通道误差 **1**、mean **0**、超 12 的样本 **0 / 350892**——即无损。
这条断言是整条链路最有说服力的检查，它同时验证了补底与 alpha 两件事。

### 两个踩过的坑，都是「靠猜」

- **按亮度硬阈值切白色**：图形边缘有一圈抗锯齿过渡像素（实测 716 px，亮度落在
  150–200 之间），切完之后它们既不算前景也不算纯底色，被原样留在背景层里。它们
  比底色亮得多，于是背景上出现一圈灰白描边（实测那圈是 `#526FA0`），图标边缘像
  糊了一层。
- **给过渡像素估半透明 alpha**：要正确合成半透明必须知道「这一像素底下原本是什么
  底色」；底色被图形盖住，靠邻域推测，差几个色阶就在深色底上显出一圈灰。所以推测
  这条路走不通，只能改成上面那种「已知底板 → 反解」。

补底色同理：早先按「该格出现最多的非白颜色」逐格取色，被图形盖住大半的那一格只剩
边缘过渡像素，直方图的赢家是一种混色。现在先统计整张图取色板（真实格色各 7 万像素
以上，混色只有几十），再让每格只在色板里选——混色压根不在候选集里。脚本对此有断言：
背景层不允许出现色板之外、样本数 > 200 的颜色。

## 依赖说明（改脚本前先读）

本机是 CLT-only，**没有 .NET SDK、没有 csc**，PowerShell 7 的 `Add-Type` 无法引用
`System.Drawing`（CS1069：找不到 `System.Drawing.Common`）。所以像素处理全部走
`Add-Type -AssemblyName System.Drawing` + `LockBits` 读写 `byte[]`，不用内联 C#。
纯 PS 每趟 1M 像素约 2.3 s，整脚本约 11 s。

## 合成到桌面时注意

- 两层都不自带圆角、不带内边距——外层圆角是系统的。
- `entry/` 的副本会覆盖 `AppScope/`，所以两处都要写：只改一处，桌面还是旧图标。
- 图形须留在安全区内：系统遮罩会裁四角，脚本断言四边各留 ≥ 17%（当前各 243 px，
  图形占画布 52.5%）。
- 48 px 下白色覆盖必须落在 8%–35%（当前 12.63%），低于该值会糊成灰边，高于则
  空格闭合、读不出图形。
