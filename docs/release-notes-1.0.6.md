# 纸见 v1.0.6

一个单点修复版本：**悬浮页签栏恢复时落点错位**（比常态低 126 px、高度被压到 42 vp、
28 vp 的底部边距整个丢掉并贴住屏幕底边），笔记页、标签页、设置页三处都能看到。

## 为什么会这样

v1.0.5 把「收起」和「展开」分成了两个档：收起用 `SCROLL_ANIMATION`，展开用
`CLICK_ANIMATION`。收起的判断是对的——`CLICK_ANIMATION` 收起时只收标题栏、页签栏
留在原地。错的是展开那一半：

| 展开档位 | 页签栏落点 | 结果 |
| --- | --- | --- |
| `CLICK_ANIMATION` | `[210,2106][1110,2232]` | 低 126 px、高 42 vp、贴住底边 |
| `SCROLL_ANIMATION` | `[210,1980][1110,2148]` | 与常态逐像素一致 |

`CLICK_ANIMATION` 是「点击场景」的动效，它假设栏是从一条迷你条展开的，所以落点按
迷你条的位置与高度算；这一页的栏从来没有进过迷你条状态，于是落在了一个既偏下又偏矮
的位置。

v1.0.5 之所以避开了 `SCROLL_ANIMATION` 展开，理由是「它会把胶囊摊成满屏宽、图标放大到
1.67 倍」。这次复现那个场景后确认：摊宽来自**到底回弹被误判成往回翻**，与档位无关。
回弹在 `yOffset` 上与「用户往回翻」完全同形，于是同一次上滑先收起、弹回又展开，而那一刻
用的是展开档——看起来就是「底栏弹跳放大」。v1.0.4 已经把到底守卫收窄成只压回弹方向
（`isAtEnd() && delta < 0`），摊宽的前提就消失了。

## 改法

两个方向都只走 `SCROLL_ANIMATION`，不再按方向换档：

```ts
const mode: HdsAnimationMode = HdsAnimationMode.SCROLL_ANIMATION;
if (hidden) {
  this.hdsTabs.applyHideAnimation(mode);
} else {
  this.hdsTabs.applyShowAnimation(mode);
}
```

判据集中在 `setChromeHidden()` 一处注释里，`AGENTS.md` §「滚动时顶栏与页签栏一起让位」
同步改写——v1.0.5 版本的那段结论（「两档必须不同」）是错的，留着它下一个动这段代码的人
还会再踩一遍。

## 验证

三个页签 × 三条恢复路径，每一步 dump 一次页签栏几何：

| 路径 | 笔记页 | 标签页 | 设置页 |
| --- | --- | --- | --- |
| 中部下滑恢复 | `[210,1980][1110,2148]` | `[210,1980][1110,2148]` | `[210,1980][1110,2148]` |
| 拉到底再上滑 | 保持收起 | 保持收起 | 保持收起 |
| 回到顶部 | `[210,1980][1110,2148]` | `[210,1980][1110,2148]` | `[210,1980][1110,2148]` |

内容区也跟着归位：笔记网格 `WaterFlow` 收起态顶边 141 px，恢复后回到 459 px；设置页
`List` 309 px、标签页 `Scroll` 459 px，与常态一致。收起态里继续上滑，内容仍在移动
（设置页「AI 服务」这一行被推出视口，恢复后回到 1029 px），不存在「收起之后划不动」。

展开过渡用半分辨率连拍（约 10 ms/帧）逐帧看：胶囊在原处由窄变宽、渐显直到常态，
没有出现摊成整行的过渡帧。（宽度不能靠像素扫描量——展开后胶囊底下压着笔记卡片，
按亮度取的包围盒会把卡片一起框进来。）
