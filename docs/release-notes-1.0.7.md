# 纸见 v1.0.7

一个视觉版本：**换掉了应用图标**，另外把设置页的两组配置调换了顺序。

## 新图标

新图标是深青 `#` 落在米色等高线底板上，由设计稿 `design/icon.png` 一张 1024² 母版
派生。仓库里**只有这一张母版**——换图时直接覆盖它，不留原始文件副本。

对比上一版的极光底玻璃 `#`，最实际的改善在最小尺寸：48 px 下字形与底板的明度落差
从 44 级升到 **100 级**。底板明亮、字形是一整片实心深色，通知栏与设置列表里那个
十几像素的位置才读得出来。

### 为什么没有拆成分层图标

分层图标（`layered_image`，前景 + 背景两层）能带来轻微的桌面视差。这里试过，结论是
这条路对这张母版走不通：

分层要求把字形从底板里抠出来，而**底板在字形底下不可见**。能抠的前提是重建底板再
逐像素解混合，但合成回原图的约束是一个硬下界：

```
a ≥ k,        k = max_c |src_c − plate_c| / headroom
```

只要底板在某个像素不等于原图，那里就**必然**有前景墨。底板是重建的、天生带几个色阶
误差，于是底板的纹理整片漏进前景层——上一版极光母版实测前景 PNG 783 KB，铺到中灰上
是一整片可见的蓝云。放大 alpha 增益会把误差放大三倍；调阈值只能两边都伤，收紧就把
字形本体也切掉。

单层图标没有这个问题：整张 PNG 就是最终像素，系统用它的圆角遮罩裁剪。代价只是没有
分层视差，而图标在 48–216 px 下看不出视差。所以 `icon` 直接指向 `$media:app_icon`。

**换母版时的判据**是「底板在字形底下是否已知」。上一版能拆是因为它是 3×3 纯色马赛克，
每格颜色可算出来，`a = (src − bg) / (255 − bg)` 是解出来的而不是猜的。渐变、极光、
玻璃、等高线纹理都属于未知，走单层。

### 检测脚本也一并修了

`scripts/gen-icon.ps1` 原来那套字形检测是从极光母版反推的，换图后有两处直接失效：

- **底板明度取样**取的是画布第一个像素，而新母版那个位置正好压着一条等高线，算出的
  阈值把整张画布框成字形（bbox 1023×1023）。现在取明度直方图的众数——底色占绝大多
  数像素，纹理只占少数。
- **48 px 对比度**写死了旧字形框坐标，换图后测的还是旧位置，「通过」这件事本身就失去
  意义。现在按实测框取样，判据取绝对值，深字浅底与浅字深底同一条公式。

顺带补了一条 17% 遮罩安全线检查，并删掉了仓库里唯一一份真正没用到的资产
（`reference/sample.jpg`，263 KB，自 MVP 起无人引用）。

## 设置页分组顺序

「阅读与编辑」移到「外观」之前。写作时随手会调的字号、行距、编辑体验放到第一屏，
主题 / 光感挡位 / 强调色这些装好之后基本不再动的排到第二组。与「AI 排在同步之前」是
同一条理由——越常用的越靠上。

只搬动顺序，文案与控件一字未改。
