# 纸见 v1.0.4

一个单点修复版本：**设置页拉到底再往上划，页签栏会往上跑、并且放得特别大再弹回去。**

## 为什么会这样

「向上翻的时候把界面让出来」这件事由一条判定驱动：`handleChromeScroll()` 读
`currentOffset().yOffset`，同向累计超过 24 vp 就收起顶栏与页签栏，反向则请回来。

问题出在「到底」这个位置。列表滚到底之后继续同向划动，容器会先给出**越过边界**的
位移，松手再弹回来。那一段回弹在 `yOffset` 上是「位置在减小」——与「用户往回翻」
完全同形，判定无法区分。于是同一次上滑先收起了页签栏，回弹时又把它请了回来。

如果只是「收起来又回来」，顶多闪一下。真正难看的是 HDS 的**展开动效**：它把一个
悬浮胶囊摊成满屏宽再收拢。实测（设置页拉到底再上滑）胶囊从 900 px 摊到 1320 px、
图标放大到 1.67 倍，然后再缩回原位——读起来就是底栏往上跑、放得特别大。

## 改法

到底期间（`scroller.isAtEnd()`）不做方向判定：既不累计、也不翻状态，并置
`scrollSeed = true`。离开底部之后的第一条事件只用来重新种基准，回弹的余量不会被
当成一次「猛推」。

判据只有这一条，因为到底时 `yOffset` 已经不是位置的度量。`moveToEdge` 这类
「滚到底」的动作同样经过这里，不需要另加分支。

## 验证

按用户原始路径复现，连拍 6 帧逐帧测量：底栏始终 900×168 px、图标 48 px、
底边距屏幕底 84 px，**没有任何一帧出现放大、淡出或上移**。三个页签各自的中段
上滑 / 下滑让位与回归都正常。

判据写进了 `AGENTS.md` §「滚动时顶栏与页签栏一起让位」，连同实测数字——这条规则
的有效期比这次修复长：任何在滚动容器上做「方向判定」的地方都会撞上同一个回弹。
